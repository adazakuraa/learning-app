## 0. 結論（推奨構成の要約）

| 項目 | 推奨 | 追加費用 |
|---|---|---|
| アプリ本体 | Vite + React + TypeScript の静的SPA | 0円 |
| ホスティング | GitHub Pages（GitHub Actions でビルド・デプロイ） | 0円 ※公開リポジトリが条件（§1-2） |

| AI生成工程 | Claude Code 等の開発エージェントに「教材 + 追加指示」を渡し、シーン定義・学習用テキスト・台本を生成。アプリとは完全分離 | 追加0円 ※既存のAIエージェント契約の範囲 |

## 1. GitHub Pages だけで実現できる範囲

### 1-1. できること
- 静的ファイル（HTML/JS/CSS/画像/音声/小〜中サイズの動画）の配信
- クライアントサイドで完結する機能すべて: 教材表示、動画再生、進捗記録（端末内）、ダッシュボード
- GitHub Actions による自動ビルド・デプロイ（教材を push すれば自動で反映）

### 1-2. 制約（重要）
| 制約 | 内容 | 影響と対策 |
|---|---|---|
| **非公開リポジトリ不可（無料プラン）** | GitHub Free では Pages は公開リポジトリからのみ公開可能。サイト自体にもアクセス制限（ログイン）をかけられない | **教材・動画がインターネット上に公開状態になる**。URLを知らなければ辿り着きにくいが、秘匿にはならない。→ 要確認事項 Q1 |
| サイト容量 | 公開サイトは 1GB 以下が推奨上限 | 動画をMP4で大量に置くと超過しうる → §4 |
| 帯域 | 月100GB程度のソフトリミット | 学習者1人なら問題なし |
| 1ファイル | Git の制限で 100MB 超は push 不可（50MB超で警告） | 動画は分割・圧縮、または別方式 |
| サーバー処理なし | DB・認証・APIキー秘匿ができない | 進捗同期は外部無料サービス、管理更新は GitHub API を利用 |

**非公開が必須な場合の無料代替**: Cloudflare Pages（非公開リポジトリから無料デプロイ可）+ Cloudflare Access（少人数まで無料でメール認証によるアクセス制限が可能）。GitHub はソース管理として引き続き使える。構成はほぼ変わらないため、後から切り替えも可能。

## 2. Notion 教材を無料で取り込む方法

| 方式 | 手間 | 安全性 | 備考 |
|---|---|---|---|
| **A. Notion の Markdown エクスポート（推奨・初期）** | 手動エクスポート → zip を `content/_inbox/` に置く | 認証情報不要で最も安全 | 画像も同梱される。取り込みスクリプトで単元フォルダへ整理 |
| B. Notion API + GitHub Actions | 初期設定のみ。以後ボタン1つ/定期実行 | トークンは GitHub Secrets に保存（ブラウザに出ない） | Notion 側の画像URLは約1時間で失効するため、取り込み時に画像をダウンロードしてリポジトリに保存する必要あり |
| C. ファイルアップロード（管理画面） | 管理画面から .md / .zip を登録 | GitHub トークンは管理者端末のみ | Phase 3 で A と同等の処理をブラウザから実行 |

- Notion API を**ブラウザから直接呼ぶ方式は採用しない**（トークン露出、CORS 非対応）。
- 推奨: まず A で運用を開始し、教材数が増えて手間になったら B を追加。

### 取り込み時の扱い
- **原本（Notionから来たテキスト）は `source.md` として無改変で保存**する。
- 見やすく整理した **学習用テキスト `lesson.md` は別ファイル**として生成・編集する。
- 生成時、原本の情報が欠落していないかをチェックする（見出し・重要語・数値・表の照合をスクリプト + 目視で実施）。

## 3. 複数端末間で学習進捗を無料同期する方法

| 方式 | 端末間共有 | 費用 | 手間 | 評価 |
|---|---|---|---|---|
| LocalStorage / IndexedDB | ✕ | 0 | なし | 単体では不十分。ただし**オフライン時の一時保存先として必須** |
| JSON エクスポート/インポート | △（手動） | 0 | 端末を替えるたびに操作 | 予備・バックアップ用として実装 |
| **Firebase Firestore（Spark 無料プラン）** | ◎ 自動 | 0（クレジットカード登録不要） | Googleアカウントでログイン1回 | **推奨**。無料枠（保存1GiB、読み取り5万回/日 等）に対し、本用途は桁違いに小さい |
| Supabase 無料枠 | ◎ | 0 | 同上 | 一定期間（約1週間）アクセスがないとプロジェクトが一時停止される。週1利用だと停止リスクがあり不採用 |
| GitHub Gist / リポジトリに保存 | ○ | 0 | 学習者端末に GitHub トークンが必要 | 学習者にトークン管理を求めるため不採用 |

### 推奨設計: ローカルファースト + 同期
1. 進捗はまず IndexedDB に記録（オフラインでも動作）。
2. ログイン済みなら Firestore に差分を送信。別端末では起動時に取得してマージ。
3. マージ規則: 完了状態は「どちらかで完了なら完了」、視聴済み区間は和集合、学習時間はセッション単位の記録を合算（二重計上しない）。
4. Firestore のセキュリティルールで **特定ユーザー(UID)のみ読み書き可能**にする。Firebase の設定値（apiKey 等）は公開前提の値であり、秘匿情報ではない。
5. 同期を使わない場合でもアプリは完全に動作する（Firebase は任意機能）。

## 4. 動画ファイルの保存・配信方法

### 4-1. 容量の見積もり（MP4方式の場合）
- 720p・スライド中心・H.264 で 1分あたり約 3〜8MB。1単元 5〜10分 → 約 15〜80MB。
- 単元が 30 を超えると GitHub Pages の 1GB 推奨上限に近づく。

### 4-2. 推奨: ブラウザ内レンダリング方式（シーン再生）
動画を「映像ファイル」ではなく **シーン定義（JSON）+ 音声 + 字幕** として保存し、アプリ内のプレーヤーが HTML/SVG/CSS アニメーションで再生する。

| 観点 | MP4方式 | シーン再生方式 |
|---|---|---|
| 容量 | 大（数十MB/単元） | 小（JSON数十KB + 音声 1〜3MB/単元、音声なしならほぼ0） |
| 画質 | 解像度固定、文字がにじむことがある | どの画面サイズでも鮮明。スマホで文字を大きくできる |
| 字幕との一致 | 別ファイルで同期 | 台本から同時生成されるため必ず一致 |
| 修正 | 再レンダリング・再アップロードが必要 | JSON の1箇所を直すだけ |
| 再生操作 | ネイティブ | 再生・停止・シーク・速度変更をプレーヤーで実装 |
| 表現力 | 何でも可 | スライド/アニメーション/ホワイトボード型に十分。実写・複雑な3Dは不向き |

- 表現方式（スライド型 / アニメーション型 / ホワイトボード型）は**シーン単位で選択・混在可能**なテンプレートとして用意する。
- **MP4 ファイルの登録・差し替えにも対応**する（外部ツールで作った動画を使いたい場合）。小さい動画はリポジトリに、大きい動画は分割・圧縮して配置。それでも収まらない場合の外部保存先（YouTube 限定公開 等）は、外部依存・広告表示の可能性があるため、必要になった時点で相談する。
- 将来、シーン定義から MP4 を書き出したくなった場合は、同じ定義を Playwright 等で録画してMP4化できる（開発機でのみ実行、無料）。

## 5. AI による動画・音声・字幕の生成工程

アプリ本体と完全に分離した「生成パイプライン」として `pipeline/` 配下に置く。アプリは生成結果のファイルを読むだけで、AI API を一切呼ばない。

```
content/<科目>/<章>/<単元>/
  unit.yaml          … 単元名・概要・順序・生成指示（追加指示）
  source.md          … 元教材（無改変）
  lesson.md          … 学習用テキスト（整理済み）
  video/
    script.yaml      … 台本（シーンごとのナレーション文・表示要素・表現方式）
    scenes.json      … プレーヤーが読むシーン定義（script.yaml から生成）
    captions.vtt     … 字幕（WebVTT）
    narration/*.mp3  … ナレーション音声（任意）
    video.mp4        … 外部動画を使う場合のみ（任意）
```

### 生成フロー
1. **入力**: `source.md` + `unit.yaml` の追加指示（例:「アニメーションを多用」「日常生活の例を入れる」）+ 共通の生成ガイドライン（`pipeline/prompts/`）。
2. **台本生成（AIエージェント）**: Claude Code 等が `script.yaml` と `lesson.md` を作成。各シーンに表現方式・表示要素・ナレーション文・「元教材のどこに対応するか」を記録。元教材にない補足は `added: true` として明示し、レビュー対象にする。
3. **検証スクリプト**: スキーマ検証、1画面の文字量上限、字幕の1行文字数・最低表示時間、原本の重要語の網羅チェック。
4. **音声生成（任意）**: `script.yaml` のナレーション文を TTS で音声化。TTS は差し替え可能なアダプタ構造（VOICEVOX / ブラウザ読み上げ / 将来の他サービス）。
5. **字幕・タイミング生成**: 音声の長さからシーンの尺と字幕のタイミングを算出し `captions.vtt` と `scenes.json` を出力。音声がない場合は文字数から読了時間を算出。
6. **管理者レビュー** → commit/push → GitHub Actions で自動公開。

### 「動画生成AI」について（正直な説明）
- Sora / Veo のような**映像生成AIは基本的に有料**で、図解や正確な文字・数式の表現が苦手なため、教材の正確性を最優先する本件の主手段には向かない。
- 本計画での「AIによる動画生成」は、**AIが台本と画面構成（シーン定義）を設計し、それを決まったテンプレートで映像化する**ことを指す。これにより内容の正確さと修正のしやすさを確保する。
- AI は特定サービスに固定しない。入力（教材+指示）と出力（`script.yaml` のスキーマ）を固定することで、どのAIでも同じ工程を実行できる。

### 音声（TTS）の選択肢
| ツール | 費用 | 品質 | 備考 |
|---|---|---|---|
| **VOICEVOX（推奨）** | 無料 | 日本語として高品質 | 開発機でローカル実行して事前生成。各キャラクターの利用規約に従い「VOICEVOX:キャラ名」のクレジット表記が必要 |
| ブラウザの読み上げ（Web Speech API） | 無料 | 端末依存でばらつく | 音声ファイル不要。フォールバックとして利用可能 |

## 6. 管理者による教材更新の方法

GitHub Pages にはサーバーがないため、「管理画面からの更新」は **GitHub API でリポジトリのファイルを直接更新する**方式とする。

- `/admin` 画面で、管理者が自分の端末に **GitHub の Fine-grained Personal Access Token（このリポジトリの Contents 書き込み権限のみ）** を一度入力 → その端末のブラウザにのみ保存（アプリのコードやリポジトリには埋め込まない）。
- 管理画面からできること（Phase 3）:
  - 科目・章・単元の追加/編集/削除/並べ替え（`unit.yaml` 等を更新）
  - 教材ファイル（Markdown/zip）のアップロード
  - 学習用テキストの編集（Markdown エディタ + プレビュー）
  - 字幕の編集（タイムライン付き）
  - 動画ファイルの登録・差し替え
  - AI生成用の追加指示の編集（`unit.yaml` の `generation.instructions`）
  - 学習進捗の確認（Firestore から読み取り）
- 保存すると commit が作られ、GitHub Actions が自動で再ビルド・公開（数分で反映）。
- 管理画面を使わず、リポジトリを直接編集したり Claude Code に依頼したりしても同じ結果になる（**データの正はリポジトリのファイル**）。
- 動画（シーン）の生成自体は管理画面からは行わず、管理画面で設定した追加指示をもとに Claude Code 等で実行する（§5）。
- 公開リポジトリの場合、管理画面自体は誰でも開けるが、トークンがなければ何も変更できない。

## 7. データ構造

### 7-1. 教材（リポジトリ内ファイル → ビルド時に JSON 化）
```yaml
# content/info-processing/subject.yaml
id: info-processing
title: 情報処理
order: 1

# content/info-processing/01-network/chapter.yaml
id: network
title: ネットワーク
order: 1

# content/info-processing/01-network/01-tcp-ip/unit.yaml
id: tcp-ip
title: TCP/IP
summary: インターネット通信の基本となるプロトコル群を学ぶ
order: 1
video:
  type: scenes        # scenes | mp4 | none
generation:
  instructions:
    - アニメーションを多用してほしい
    - 前提知識がない人でも理解できるようにしてほしい
```

ビルド時に `pipeline/build-content` が全ファイルを走査し、`catalog.json`（科目/章/単元の一覧）と単元ごとの本文 JSON（Markdown→HTML 変換済み、目次付き）を生成する。

### 7-2. 進捗（IndexedDB / Firestore）
```ts
type UnitProgress = {
  unitId: string;
  video: {
    watchedRanges: [number, number][]; // 視聴済み区間（秒）→ 視聴率を算出
    lastPosition: number;              // 続きから再生
    completed: boolean;                // 視聴率が閾値(既定90%)以上
  };
  text: {
    maxScrollRatio: number;            // どこまで読んだか
    lastHeadingId?: string;            // 続きから読む
    completed: boolean;
  };
  completedAt?: string;
  lastStudiedAt: string;
  totalStudySeconds: number;
};

type StudySession = { id: string; unitId: string; mode: 'video'|'text'; start: string; seconds: number; device: string };

type Settings = {
  completionRule: 'both' | 'either' | 'video' | 'text'; // 単元完了の判定方法（設定で変更可能）
  videoCompleteThreshold: number; // 既定 0.9
  playbackRate: number;
  captionSize: 'm' | 'l' | 'xl';
};
```
- 学習時間は「画面が表示中かつ操作/再生中」の時間のみ計上（タブ非表示・長時間無操作は除外）。
- 科目・章の進捗率は単元の完了状態から都度算出（保存しない）。

## 8. 画面構成

| 画面 | パス | 主な内容 |
|---|---|---|
| ホーム/ダッシュボード | `/` | 全体進捗、科目ごとの進捗バー、学習済み/未学習単元数、累計学習時間、最近学習した単元（続きから） |
| 科目一覧 | `/subjects` | 科目カードと進捗率 |
| 科目詳細 | `/subjects/:subjectId` | 章ごとの進捗バーと単元リスト（動画/テキストの完了マークを個別表示） |
| 単元学習 | `/units/:unitId?tab=video\|text` | 上部タブで動画⇔テキスト切替。動画画面に「テキストで復習」、テキスト画面に「この節を動画で見る」リンク。完了状態の表示 |
| 設定 | `/settings` | 完了判定ルール、字幕サイズ、同期ログイン、JSON エクスポート/インポート |
| 管理者 | `/admin/*` | 教材管理、動画・字幕・テキスト管理、生成指示、進捗確認 |

- 順番による制限はなく、どの単元も自由に選択可能。
- スマホ: 下部ナビゲーション、動画は画面幅いっぱい、字幕は大きめ既定。PC/タブレット: テキスト画面に目次サイドバー。
- デザイン: ダークモード基本（背景 #0f1115 前後、本文は純白ではなく #d8dce3 前後、強調色1色のみ）、ライトモードも切替可能。ゲーム要素なし。

## 9. 技術スタック

| 層 | 採用 | 理由 |
|---|---|---|
| ビルド | Vite | 高速・静的出力・GitHub Pages と相性が良い |
| UI | React + TypeScript | 動画プレーヤー・進捗管理など状態の多い画面に適する。型でデータ構造を固定 |
| ルーティング | React Router（GitHub Pages 用に 404.html フォールバック） | 直接 URL アクセスに対応 |
| スタイル | CSS Modules + CSS 変数（デザイントークン） | 依存を増やさずダーク/ライトを管理 |
| Markdown | unified（remark/rehype）をビルド時に実行、数式は KaTeX、コードはシンタックスハイライト | 実行時の負荷を減らし、表・画像・数式に対応 |
| ローカル保存 | IndexedDB（小さなラッパー） | 容量・信頼性で LocalStorage より有利 |
| 同期（任意） | Firebase Auth + Firestore | 無料・カード不要・リアルタイム同期 |
| テスト | Vitest（ロジック）、Playwright（スマホ/PC 表示の確認） | |
| CI/CD | GitHub Actions → GitHub Pages | push で自動公開 |
| PWA | Phase 4 以降で検討（オフライン学習・ホーム画面追加） | 過剰実装を避ける |

## 12. 改訂2: 回答を反映した決定事項

### 12-1. 動画は MP4 にする（容量問題の解決策）
- GitHub Pages の「1GB」は **1サイト（= 1リポジトリ）あたり**の推奨上限。リポジトリを分ければそれぞれに 1GB ずつ使える。
- 構成:
  - `learning-app`（アプリ本体・教材テキスト）→ `https://<user>.github.io/learning-app/`
  - `learning-videos-1`, `learning-videos-2`, …（MP4・字幕のみ）→ `https://<user>.github.io/learning-videos-1/...`
  - 同じ `github.io` ドメインのため、字幕(VTT)読み込みでのクロスオリジン問題も起きない。
  - 1リポジトリが 800MB 程度に達したら次のリポジトリを作る運用。単元ごとの動画URLは `unit.yaml` に記録するので、どのリポジトリにあってもアプリ側は意識しない。
- 制約: 1ファイル 100MB 未満（720p・H.264・10分なら 30〜60MB 程度で収まる見込み）。動画リポジトリも公開リポジトリになる。
- 注意: GitHub の規約上、Pages を「汎用の大容量ファイル置き場」として使うことは想定外とされている。自サイト用の動画配信は通常の範囲と考えるが、極端に増やさないこと（数GB程度まで）。
- 生成方法: シーン定義（JSON）をヘッドレスブラウザで描画 → ffmpeg で MP4 化。**この Claude Code のクラウド環境に Chromium と ffmpeg があることを確認済み**のため、スマホからの依頼だけでレンダリングできる。シーン定義はリポジトリに残すので、修正時は定義を直して再レンダリングするだけ。
- Mac の Safari で確実に再生できるよう、H.264 + AAC、`faststart` 付きで出力する。

### 12-2. 進捗は GitHub に保存する（Firebase 不採用）
- ご指摘のとおり Firebase は必須ではない。端末間のリアルタイム同期は不要なので、GitHub 保存で十分。
- 仕組み:
  - 非公開リポジトリ `learning-progress` を作成し、`progress.json` を保存（進捗を公開しないため）。
  - 学習者の Mac のブラウザに、**そのリポジトリだけ書き込める Fine-grained トークン**を一度だけ設定（管理者が発行して設定してあげる想定）。
  - 「読了」「単元完了」ボタンを押したとき、および学習終了時（タブを閉じる/一定間隔）に GitHub へ保存。起動時に読み込み。
  - 管理者は管理画面（同じリポジトリを読む）または GitHub アプリで進捗を確認できる。
  - トークン未設定やオフライン時は端末内に保存し、次回まとめて送信。
- リスク: トークンは学習者のブラウザ内に保存されるが、権限は進捗リポジトリへの書き込みのみに限定するため、漏れても影響は進捗データに留まる。

### 12-3. 管理者はスマホのみ
- 開発・教材生成・動画レンダリング・音声生成はすべて **Claude Code（クラウド）と GitHub Actions** で行い、管理者のPCは不要とする。
- 管理画面はスマホ操作を前提に設計（片手で操作できるフォーム、テキスト/字幕編集はスマホ向けエディタ）。
- VOICEVOX は Linux 版エンジンをクラウド上で動かして音声を作る。エンジンのダウンロードがこの環境のネットワーク設定で許可されるかは Phase 2.5 で検証する。不可の場合は字幕のみで構成し、代替手段を相談する。

### 12-4. 完了判定は手動ボタン
- テキスト: 「読了」ボタンで手動完了。
- 単元: 「単元を完了する」ボタンで手動完了（動画・テキストの完了状態とは独立）。
- 動画: 視聴率と続きの再生位置は自動記録（表示用）。視聴完了は 90% 以上で自動マーク（必要なら手動に変更可）。
- §7 の `completionRule` 設定は不要になったため削除する。

### 12-5. 学習者の環境
- 学習者は Mac（Safari/Chrome を想定）、管理者はスマホ。両方で動作確認する。
